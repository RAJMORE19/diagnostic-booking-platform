# 4. Microservices List

We will deliberately keep the platform around **6 meaningful services**.

### 1. Auth Service

Responsibilities:

* Registration
* Login
* Authentication
* User profile
* JWT/token handling
* Role-based access

Example:

```text
POST /auth/register
POST /auth/login
GET  /auth/profile
```

---

### 2. Test Catalog Service

Responsibilities:

* Blood test catalog
* Test details
* Categories
* Prices
* Search/filter
* Admin test management

```text
GET    /tests
GET    /tests/{id}
POST   /admin/tests
PUT    /admin/tests/{id}
DELETE /admin/tests/{id}
```

---

### 3. Cart Service

Responsibilities:

* Add tests
* Remove tests
* Update quantity
* Calculate cart value

Redis can be used where appropriate for fast temporary/cart-related data.

```text
GET    /cart
POST   /cart/items
DELETE /cart/items/{id}
```

---

### 4. Booking Service

This is the primary business service.

Responsibilities:

* Patient details
* Home collection
* Diagnostic-center collection
* Address
* Date
* Time slot
* Booking creation
* Booking history
* Cancellation/rescheduling
* Booking status

```text
POST /bookings
GET  /bookings
GET  /bookings/{id}
PUT  /bookings/{id}/cancel
```

---

### 5. Payment Service

Initially:

**Simulated payment only.**

Responsibilities:

* Payment request
* Payment status
* Success/failure simulation
* Payment reference

```text
POST /payments
GET  /payments/{id}
```

Real payment gateway integration will be **Phase 2 / Optional**.

---

### 6. Notification Service

Responsibilities:

* Booking confirmation
* Payment confirmation
* Cancellation notification
* Notification events

Initially this can use application-level notification simulation/logging rather than integrating an expensive external provider.

---

### Database strategy

We will **not create six independent database servers**.

Initial architecture:

```text
AWS RDS PostgreSQL
        │
        ├── application schemas/tables
        │
        └── transactional data

Redis
        │
        ├── Cache
        ├── Temporary data
        └── Rate limiting
```

During implementation, we will explicitly discuss:

**Shared database vs database-per-service**

and the trade-offs involved.

```text
                    CLOUD-INDEPENDENT
                     APPLICATION
                          │
             ┌────────────┴────────────┐
             │                         │
             ▼                         ▼
        AWS Deployment            Azure Deployment
             │                         │
             ▼                         ▼
          AWS EKS                    AKS
             │                         │
             ▼                         ▼
        AWS Services              Azure Services
```

Conceptual mapping:

| AWS                    | Future Azure                                                         |
| ---------------------- | -------------------------------------------------------------------- |
| VPC                    | VNet                                                                 |
| EKS                    | AKS                                                                  |
| ECR                    | Azure Container Registry                                             |
| RDS PostgreSQL         | Azure managed PostgreSQL                                             |
| S3                     | Azure Blob Storage                                                   |
| IAM                    | Microsoft Entra ID + Azure RBAC                                      |
| ALB                    | Azure Application Gateway / appropriate Azure load-balancing service |
| Route 53               | Azure DNS                                                            |
| CloudWatch             | Azure Monitor                                                        |
| Secrets Manager        | Azure Key Vault                                                      |
| Terraform AWS provider | Terraform AzureRM provider                                           |

But we will **not treat these as one-to-one identical services**.

The future documentation will specifically explain:

* Networking differences
* IAM differences
* Kubernetes differences
* Load-balancing differences
* Managed database differences
* Storage differences
* Security differences
* Terraform provider differences
