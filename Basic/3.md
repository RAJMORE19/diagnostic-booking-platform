3. WHY PUBLIC + PRIVATE SUBNETS?

This is one of your most important interview concepts.

Public subnet

A subnet is considered public when its route table has a route to an Internet Gateway.

Example:

0.0.0.0/0
↓
Internet Gateway

Private subnet

A private subnet does not directly route to the Internet Gateway.

For workloads that need outbound Internet access, it can use:

Private Subnet
↓
NAT Gateway
↓
Internet Gateway
↓
Internet

Why?

We don't want:

Internet
↓
RDS

We want:

Internet
↓
ALB
↓
Private EKS
↓
Private RDS

12. PUBLIC SUBNETS

Add:

resource "aws_subnet" "public" {
count = length(var.public_subnet_cidrs)

vpc_id                  = var.vpc_cidr
cidr_block              = var.public_subnet_cidrs[count.index]
availability_zone       = var.availability_zones[count.index]
map_public_ip_on_launch = true

tags = {
Name = "${var.name}-public-${count.index + 1}"
}
}

We are creating multiple AZs because production availability should not depend on a single Availability Zone.

13. PRIVATE SUBNETS

15. NAT GATEWAY DECISION

For production:

Private EKS
↓
NAT Gateway
↓
Internet Gateway

NAT Gateway itself is placed in a public subnet.

Private workloads use it for outbound Internet access.

But NAT Gateway costs money.

For a personal learning project, don't blindly create multiple NAT Gateways.

For Day 3:

Production

Prefer NAT Gateway architecture appropriate to availability and traffic requirements, potentially one per AZ depending on resilience/cost requirements.

50. DAY 3 INTERVIEW — AWS

Q: Why use a VPC?

> A VPC gives us an isolated networking boundary where I control IP ranges, subnets, routing and network security. In this project I use public subnets for internet-facing components such as the future ALB and private subnets for EKS workloads and RDS.

Q: Public vs private subnet?

> The key distinction is routing. A public subnet has a route to an Internet Gateway, while a private subnet does not directly route to the Internet Gateway. Private workloads can use a NAT Gateway for outbound access when required.

Q: Why is RDS private?

> RDS contains transactional and potentially sensitive application data, so there is no reason to expose PostgreSQL directly to the Internet. I restrict access to the application security group on port 5432.

Q: What is NAT Gateway?

> NAT Gateway allows resources in private subnets to initiate outbound Internet connections without accepting unsolicited inbound Internet traffic. The NAT Gateway is deployed in a public subnet and uses the Internet Gateway for outbound connectivity.

Q: Security Group vs NACL?

> A Security Group is a stateful, instance or ENI-level firewall, while a Network ACL is stateless and operates at the subnet level. In this project Security Groups are my primary mechanism for workload-level access control.

---

51. DAY 3 INTERVIEW — TERRAFORM

Q: Why Terraform?

> Terraform lets me define AWS infrastructure as code. Instead of manually creating networking, ECR, RDS and later EKS resources, I can version the configuration, review changes with plan, reproduce environments and reduce configuration drift.

Q: What is Terraform state?

> State is Terraform's record of the infrastructure resources it manages and their attributes. Terraform compares the desired configuration with the state and real infrastructure to determine what changes are required.

Q: Why remote state?

> In a team environment, local state creates collaboration and recovery problems. Remote state gives us centralized storage and supports controlled access and state locking, so multiple engineers don't accidentally modify infrastructure simultaneously.
