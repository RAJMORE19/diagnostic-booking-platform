# 2. Why Terraform?

Be able to explain this in an interview:

> Terraform allows us to define infrastructure as code. Instead of manually creating AWS resources through the console, I can define VPCs, subnets, IAM roles, security groups, EC2, RDS and other resources in code. # 4. Terraform Provider

AWS provider tells Terraform how to communicate with AWS.

Example:

```hcl
provider "aws" {
  region = "ap-south-1"
}
```

Flow:

```text
Terraform
   ↓
AWS Provider
   ↓
AWS API
   ↓
AWS Resources
```

---

# 5. Terraform Resource

A resource creates or manages infrastructure.

Example:

```hcl
resource "aws_s3_bucket" "example" {
  bucket = "my-example-bucket"
}
```

Understand:

```text
resource
   ↓
resource type
   ↓
resource name
   ↓
configuration
```

---

# 6. Terraform Data Source

Important difference:

```text
Resource
   ↓
CREATE / MANAGE
```

while:

```text
Data Source
   ↓
READ existing information
```

Example:

```hcl
data "aws_caller_identity" "current" {}
```

Think:

```text
resource = create/manage
data     = lookup/read
```

# 13. Terraform State

This is one of the **most important Day 6 topics**.

Terraform needs to know:

```text
What did Terraform create?
What exists?
What changed?
What should be updated?
```

Terraform stores this information in:

```text
terraform.tfstate
```

Concept:

```text
Terraform Code
      │
      ↓
Terraform State
      │
      ↓
AWS Infrastructure
```

---

# 14. Why Terraform State Matters

Suppose Terraform created:

```text
VPC
EC2
RDS
ALB
```

Terraform records resource information in state.

Later:

```text
terraform plan
```

Terraform compares:

```text
Configuration
      +
State
      +
Real AWS Infrastructure
```

and determines the required changes.

---

# 15. NEVER Store Production State Locally

For a team:

```text
Local
terraform.tfstate
```

is not ideal.

Use:

```text
S3
 ↓
Remote Terraform State
```

Architecture:

```text
Developer 1 ─┐
             │
Developer 2 ─┼──→ S3 Backend
             │
CI/CD ───────┘
```

---

# 16. State Locking

Multiple engineers shouldn't modify Terraform state simultaneously.

Learn:

```text
State
 +
Locking
```

For your AWS project, understand the traditional pattern:

```text
S3
 ↓
Terraform State

DynamoDB
 ↓
State Locking
```

Also know that modern Terraform workflows may use newer S3-native locking capabilities, so don't claim DynamoDB is the only available mechanism.

---

# 17. Terraform Variables

Don't hardcode everything.

Bad:

```hcl
region = "ap-south-1"
```

Better:

```hcl
variable "aws_region" {
  type    = string
  default = "ap-south-1"
}
```

Then:

```hcl
provider "aws" {
  region = var.aws_region
}
```

---

# 18. Terraform Outputs

Useful for displaying important information.

Example:

```hcl
output "vpc_id" {
  value = aws_vpc.main.id
}
```

After:

```bash
terraform apply
```

you can see:

```text
vpc_id = "vpc-xxxxxxxx"
```

---

# 19. Terraform Locals

Use locals for reusable calculated values.

Example:

```hcl
locals {
  project_name = "blood-test-platform"
  environment  = "dev"
}
```

Then:

```hcl
"${local.project_name}-${local.environment}"
```

# 20. Terraform Modules

This is where your Terraform becomes production-grade.

Instead of:

```text
main.tf
 └── 1000 lines
```

create reusable modules:

```text
modules/
│
├── vpc/
├── iam/
├── ecr/
├── rds/
├── ec2/
├── alb/
└── monitoring/
```

Then:

```text
environment
     │
     ├── dev
     ├── staging
     └── prod
```

# 24. Terraform IAM

Create:

```text
IAM Role
   ↓
EC2
```

Permissions should follow:

```text
Least Privilege
```

For example:

```text
EC2
 ↓
ECR pull
 ↓
Secrets Manager read
```

Don't give:

```text
AdministratorAccess
```

just because it is easier.

---

# 25. Terraform RDS

Terraform should manage:

```text
RDS
│
├── PostgreSQL
├── Subnet Group
├── Security Group
├── Storage
├── Backup
└── Configuration
```

Production principle:

```text
Application
    ↓
Private Network
    ↓
RDS
```

Avoid publicly exposing the database unless there is a specific justified requirement.

# 29. Terraform Dependency Graph

Very important concept.

Terraform automatically understands dependencies.

Example:

```text
VPC
 ↓
Subnet
 ↓
EC2
 ↓
ALB Target Group
 ↓
Listener
```

You generally shouldn't manually create everything in a specific order.

Terraform builds a dependency graph.

```text
Terraform Configuration
        ↓
Dependency Graph
        ↓
Resource Creation
```
